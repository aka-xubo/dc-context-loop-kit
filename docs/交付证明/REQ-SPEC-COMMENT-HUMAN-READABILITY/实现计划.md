## 上下文盘点

### 事实来源

- 已确认 REQ：`REQ-SPEC-COMMENT-HUMAN-READABILITY`。
- 已确认 SPEC：`SPEC-001`，包含 `SCN-001` 至 `SCN-004`、`CHK-001` 至 `CHK-004`、`AST-001` 至 `AST-008`。
- 生产 SPEC comment 唯一入口：`.agents/skills/dc-context-loop-kit/dc-context-loop/scripts/prepare_event.py::render_spec`。
- SPEC 草案入口：`render_spec_draft.py`，其正式渲染复用 `prepare_event.render`。
- 既有契约允许完整 SPEC 或 `base_spec_ref + changes` 增量；脚本不读取历史、不自动合并增量。

### 发现与决策

1. 完整 SPEC 使用“SCN 索引短表 + 场景纵向详情 + CHK/AST 纵向详情”，避免长 When/Then 填入宽表格。
2. CHK 详情同时显示 ID、责任、类型、必需/阻断和所属 SCN 标题/业务结果。
3. AST 详情同时显示 ID、描述、所属 CHK 责任，以及 `outcome_refs` 对应的 SCN 标题、Then ID 和 Then 文本。
4. 增量 comment 只展示事件携带的新增/修改对象；基础 SPEC 对象不会被脚本隐式复制。引用到基础 SPEC 的对象必须由上游先合并为完整快照后再生成完整 comment；本次不伪造或复制历史文本。
5. 所有展示文本从传入的结构化 SPEC 派生；机器 YAML 仍由原始事件生成。
