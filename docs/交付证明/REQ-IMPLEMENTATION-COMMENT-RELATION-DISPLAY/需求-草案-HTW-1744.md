# IMPLEMENTATION 评论关系展示优化

## 当前说明

本文件是 Issue HTW-1744 的需求草案。负责人已确认本需求；正式 REQ 事件将把同一份业务定义写入 Issue 评论时间线，作为后续 SPEC 的线上前置材料。

## 人类可读摘要

### 需求陈述

查看 IMPLEMENTATION 评论的用户能够直接理解验收场景、实现切片、验收检查和具体验收行为之间的对应关系，而不需要在重复的编号列表和章节之间手工比对。

### 业务结果

- 用户能够从一处关系视图看懂每个实现切片服务的验收场景、验证责任和具体验收行为。
- 评论优先展示业务语义，并保留稳定 ID 作为辅助追踪信息。
- 相同的实现切片及其 CHK/AST 关系不再由“绑定上下文”和“已完成内容”重复展示。
- 人类评论保持纯 Markdown 兼容，同时机器事件继续保留完整结构化引用。

### 范围内

- 优化 IMPLEMENTATION 事件的人类可读评论布局。
- 用一张关系表统一展示 SCN、实现切片、CHK 和 AST 的语义及稳定 ID。
- 关系表以一个 AST 为一行，使每个可验收行为具有明确的场景、切片和检查归属。
- 将现有顶层规格编号长列表改为覆盖摘要，不再让编号承担主要解释职责。
- 删除与关系表重复的“已完成内容”章节，并将仍需展示的切片信息并入关系表。
- 仅使用 Multica 评论能够稳定呈现的纯 Markdown；不依赖 HTML 标签、单元格内嵌套列表、CSS 或 JavaScript。
- 机器 YAML 继续保留 `spec_refs`、`completed_items.check_refs` 和 `completed_items.assertion_refs`，供校验、路由和验收使用。

### 范围外

- 不改变 REQ、SCN、CHK、AST 的业务语义、稳定 ID 或引用关系。
- 不改变 IMPLEMENTATION 事件机器 YAML 的既有字段含义。
- 不改变 ACCEPTANCE 评论中的 RUN、ART、逐 AST 结果和证据展示。
- 不把评论展示改成图片、独立 HTML 页面或需要前端运行时支持的交互界面。
- 不在 IMPLEMENTATION 事件中复制并保存另一份 SCN、CHK 或 AST 自然语言定义。

### 约束

- Issue 评论中的关系语义必须由当前有效 SPEC 与 IMPLEMENTATION 的结构化引用一致地推出，不能手工维护第二份规格内容。
- 展示结果不得使用 `<br>` 或其他 HTML 标签，也不得依赖 Markdown 表格单元格中的嵌套有序或无序列表。
- 当当前有效 SPEC 无法解析，或 SCN、CHK、AST、实现切片引用缺失或不匹配时，不得生成看似完整的关系表；必须阻断评论生成并报告具体缺口。
- 评论可读性优化不得削弱发布前 Schema、引用一致性、Git 绑定和完成前复核门禁。
- 继续沿用现有事件结构、脚本和测试模式，避免为纯展示需求引入新的交付实体。

### 依赖

- 无业务依赖。

### 未决事项

- 无。

### 发布说明

根据 HTW-1744 和当前讨论建立 IMPLEMENTATION 评论关系展示优化需求。
