# Test Data Policy

## 强制标识

接口测试创建的数据必须使用：

```text
dp_test_<requirement_id>_<run_id>_
```

同一次运行的名称、编码、标题、备注或专用测试标签使用同一前缀。字段长度受限时可以缩短，但证据中必须保留完整映射。

## 隔离优先级

1. 项目已有事务回滚机制。
2. 独立测试数据库或临时数据库。
3. 独立 Schema、Namespace 或 Tenant。
4. 唯一前缀加定向清理。

## 删除保护

- 删除必须同时匹配 `run_id` 和合法前缀。
- 目标数据不带合法前缀时拒绝删除。
- 禁止无条件删除、清库或重置共享环境。
- 清理后再次查询，确认前缀数据为零。

前缀缺失产生 `TEST_DATA_PREFIX_INVALID`；清理失败产生 `TEST_DATA_CLEANUP_FAILED`。两者都会使最终验收为 `FAIL`。

## 敏感信息

日志和 Artifact 必须脱敏。不得保存 Token、密码、密钥或完整个人敏感信息。
