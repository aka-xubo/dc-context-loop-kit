# TDD Rules

## 垂直切片

每次只处理一个已确认检查项中的一个可观察行为：

```text
行为测试 1 → RED → 最小实现 1 → GREEN
行为测试 2 → RED → 最小实现 2 → GREEN
```

不要先写完全部测试再集中实现。每次 GREEN 后依据已经学到的工程事实选择下一个切片，但不得删除已确认矩阵中的必需检查项。

## 有效 RED

RED 必须满足：

- 测试能够编译或启动。
- 测试数据和依赖配置有效。
- 失败原因是目标行为尚未实现或不符合已确认断言。
- 失败不是语法、环境、Fixture 或无关测试问题。

无法获得有效 RED 时停止并记录原因，不得把无效失败当作有效 RED。

## 最小 GREEN

- 只实现让当前行为测试通过的最小生产改动。
- 不提前实现尚未进入切片的推测行为。
- 不降低断言，不把期望值改成当前错误行为。
- 运行同一聚焦测试直到通过。

## 重构

只在相关测试绿色时重构。每次有意义的重构后重新执行聚焦测试。重构不得改变已确认业务命题。

## 每轮检查

```text
[ ] 测试描述业务行为而非内部实现
[ ] 测试使用公开代码接口
[ ] 测试因预期原因失败
[ ] 生产改动是当前行为的最小实现
[ ] 同一测试在实现后通过
[ ] 重构只发生在绿色状态
```
